# 退款预览与用户确认操作规程（模拟业务）

## 预览与提交是两件事
用户明确申请退款后，系统在服务端核验当前订单、金额、版本及资格，创建 WAITING_CONFIRMATION 的预览，向用户展示订单号和金额。此阶段退款申请表中尚不应出现新记录。聊天中“好的”“谢谢”等模糊文字不能替代确认 API 或确认按钮。

## 确认凭据与时效
确认凭据只在首次预览响应交付一次；服务端不保存明文凭据。凭据有效期为十五分钟，过期不能擅自续期。重复查询工作流不可取回原明文凭据。用户丢失凭据，需要按原工作流规则取消旧预览并重新发起申请；不能让模型生成或猜测确认凭据。

## 写入完成后的用语
确认后返回 ACCEPTED / REQUEST_ACCEPTED 表示退款申请已经受理，而不是退款款项已经到账。重复确认必须由业务端使用既有幂等键核对同一结果，不得新增第二笔申请。无法确认后台写入时保留 UNKNOWN_OUTCOME 并查询原业务结果，不能创建新请求冒险重试。

## Agent 行为边界
RAG 可以回答确认流程，但不得调用受保护的退款提交能力；真正提交只能由独立的退款确认工作流在服务端验证后发起。
